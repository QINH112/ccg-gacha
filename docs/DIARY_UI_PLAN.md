# 「日记」界面 UI 升级方案

> 状态：**设计稿阶段（未改 `game.js`）**。本文档是方案与实施账本，用户确认视觉稿后才进入代码实施。
> 决策来源：2026-11-20 与用户确认的 5 项选择（见 §2）。
> 生成图目录：`D:\kaifa\design\diary\`（所有母版、底图、效果图、审阅图只写这里，不进游戏包）。

## 1. 目标

把现有三个独立入口 **邮箱 / 每日与每周任务 / 星界成就** 合并为一个名为 **「日记」** 的界面：

- 首页只保留 **一个**「日记」入口；
- 日记内用 **三个页签**（邮件 / 任务 / 成就）承载原有内容，任务内再分「每日 / 每周」；
- 视觉上是 **深蓝皮革日记本 + 金色烫印 + 星空内页**，与现有星界风格同源，但更像一本实体手记；
- 本轮只产出 **一张完整效果图 + 设计文档**，用户确认后再改 `game.js`。

不改变的内容：云存档、OpenID 隔离、云数据库结构、抽卡/签到/商店/牌组/战斗规则、奖励数值与领取接口。

## 3. 信息架构

### 3.1 首页入口

```text
当前：邮件 | 任务 | 成就 | 我的牌组 | 对战 | 对战记录      （第二排 6 个）
改后：日记（聚合入口，带可领取数字角标） | 我的牌组 | 对战 | 对战记录
```

- 三个旧图标从首页移除，位置合并为一个 **「日记」** 图标；
- 图标右上角显示 **可领取总数**（邮件可领取数 + 任务可领取数 + 成就可领取数），没有可领取时只显示小红点、不显示数字；
- 点击进入日记，默认停在 **有红点/可领取最多的页签**，没有可领取时停在「任务」。

### 3.2 日记内部

```text
日记
├── 顶部：返回 + 标题「日记」+ 副标题（日期/页数）
├── 摘要条：今日可领取 N 项 + 一键领取
├── 页签：邮件(2) | 任务(5) | 成就(3)
└── 内容区
    ├── 邮件：邮件列表（标题/日期/剩余天数/奖励/领取）
    ├── 任务：每日 | 每周 二级切换 + 任务列表 + 进度条
    └── 成就：阶段进度 + 成就列表
```

- **一键领取只作用于当前页签**，与现有 `claimAllMail` / `claimAllTaskRewards(scope)` 语义一致；
- 任务页签的「每日 / 每周」沿用现有 `state.taskTab`，避免新增状态；
- 页签上显示数量；数量为 0 时不显示角标。

### 3.3 状态与数据映射（不改云函数）

| 日记元素 | 现有状态 / 接口 | 说明 |
| --- | --- | --- |
| 邮件列表 | `state.mail` | `claimOneMail(id)` / `claimEveryMail()` 复用 |
| 邮件剩余天数 | `mail.expiresAt` | 与现有 `renderMail` 相同的天数算法 |
| 每日任务 | `state.tasks.daily.tasks` + `.bonus` | `claimTaskReward({scope:"daily"})` |
| 每周任务 | `state.tasks.weekly.tasks` + `.bonus` | `claimTaskReward({scope:"weekly"})` |
| 成就 | `state.tasks.achievements` | `claimTaskReward({scope:"achievement"})` |
| 红点 | `state.redDots.mail/tasks/achievements` | 聚合为日记角标 |
| 一键领取 | `claimTaskReward({bonus:true})` | 现有逻辑已支持 bonus |

### 4.4 形状与质感

- 卡片圆角 12，内描边 1px，左侧 2px 金色竖条强调；
- 按钮：金色渐变（`#E8C77A` → `#C9A24B`），圆角 9，深棕字；未完成用描边按钮；
- 页签：激活态为金色「书签」形状，非激活为半透明描边；
- 分隔线：中间带菱形星标的金色细线；
- 书页边缘：左右各留 14–18px 皮革边，底部有纸张层叠与丝带；
- 所有装饰都不得压住文字；正文区域对比度 ≥ 4.5:1。

- 左右内容边距 16；卡片宽 343；

- 430×932 上卡片高度 126、行距 12，内容自然撑满，不允许下半屏整片空。

## 6. 交互

| 操作 | 行为 |
| --- | --- |
| 点页签 | 切换内容，记忆 `state.diaryTab`，列表回到顶部 |
| 左右滑内容区 | 切页签（可选，第二阶段） |
| 点条目 | 展开详情（邮件正文 / 任务说明），不新增页面 |
| 点领取 | 复用现有接口，按钮进入 loading，成功后变「已领取」 |
| 点一键领取 | 领取当前页签全部可领取项，toast 汇总数量 |
| 返回 | 回首页，保留页签位置 |
| 下拉 | 不做下拉刷新，避免与云存档刷新冲突 |

动效：页签切换 180ms 淡入 + 8px 上移；领取成功按钮 120ms 缩放；不做整屏翻页动画。

## 7. 实施计划（用户确认后执行）

### P1 首页入口合并

- `game.js`：
  - `HOME_ART_PATHS` 增加 `diary`，移除 `mail` / `tasks` / `achievements` 的菜单引用（素材文件先保留，便于回滚）；
  - `HOME_MENU_ART` 改为 `["sign","history","collection","workshop","shop","adjustAnnouncement","diary","decks","battleSetup","battleHistory"]`；
  - `HOME_ART_RECTS` 第二排改为 4 个居中图标（日记稍大），具体坐标在实施时用 `tools/render_*` 出图核对；
  - `activate()` 中 `id==="diary"` → `openDiary()`。
- 新素材：`assets/ui/home/diary.png`（132×141 或 150×150），本轮不生成，确认后单独出图。

### P2 日记页面

- `state`：新增 `diaryTab:"tasks"`、`diaryScroll:0`（或复用 `state.scrollY`）；
- 新增 `renderDiary()`，拆出 `renderDiaryTabs()` / `diaryMailRow()` / `diaryTaskRow()` / `diaryAchievementRow()`；
- `render()` 增加 `screen==="diary"` 分支；
- 删除或重定向旧 `renderMail` / `renderTasks` / `renderAchievements`：`switchScreen("mail")` 先重定向到 `diary` + `mail` 页签，观察一周无回滚需求后再删旧函数；
- `NO_TAP_LOCK` 加 `diary`、`diaryTab`；
- `resetOverlays()` 增加 `diaryTab` 清理规则（切屏保留页签，覆盖层清空）。

### P3 红点与角标

- 新增 `diaryClaimableCount()`；
- 首页 `drawRedDot` 改为 `drawBadge(count)`，数字 > 99 显示 `99+`；
- 日记页签同步数字角标；
- 领取成功后重新计算，不依赖整页 refresh。

### P4 背景与验收

- 背景：优先用程序化渐变 + 星点（零包体），效果不足再引入压好的 JPG（目标 ≤ 220KB，主包剩余约 1.1MB）；
- 三尺寸截图：375×812、430×932、320×568；
- 跑校验：

```bash
py tools/validate_visual_assets.py
py tools/validate_ui_overlay_rules.py
py tools/validate_runtime_budget.py
py tools/validate_package_limits.py
```

## 10. 其他 UI 升级建议（决定权在用户）

1. **首页重排为 5+4 居中**：合并后第二排只剩 4 个，建议整体重排而不是留空洞。
2. **日记加第四个页签「战报」**：把 `battleHistory` 收进来，与「日记」叙事最契合；本轮先不做。
3. **统一服务页骨架**：邮箱/任务/成就/公告现在标题层级和按钮位置各不相同，建议统一成「标题 + 摘要条 + 列表 + 底部说明」。
4. **顶部资源栏加经验环**：现在只有 Lv 数字，加一圈经验进度，抽卡/对战的正反馈更完整。
5. **红点体系统一**：所有可领取入口收敛到日记角标，减少首页红点噪音。
6. **空态插画**：现在空列表只有一行字，建议统一用「熄灭的蜡封 / 空星图」小插画。
